1. Logiques et choix de conception
1.1 Stack technique
Le projet est développé avec la stack suivante :
   •     Symfony (framework PHP principal)
   •     RabbitMQ — gestion des événements différés (arrivée de flotte, fin de construction, etc.)
   •     Mercure — notifications temps réel vers le navigateur du joueur
   •     MariaDB + Doctrine ORM — persistance de l'état du jeu
   •     Docker — conteneurisation de l'ensemble des services


       Le calcul du combat reste en PHP dans un service Symfony dédié. Un micro-service Python séparé
       a été évalué mais rejeté : le système de combat est déterministe et ne requiert pas de calcul intensif.
       Ajouter un container Python introduirait de la complexité réseau sans bénéfice réel à ce stade.




1.2 Modèle de temps — pseudo temps réel
Le jeu ne fonctionne pas en temps réel strict. Le modèle retenu est le suivant :
   •     Chaque action planifiée (envoi de flotte, construction, recherche) génère un message
         RabbitMQ avec un délai (TTL ou delayed exchange).
   •     À l'échéance, le consumer RabbitMQ traite l'événement : résolution du combat, livraison
         des vaisseaux, fin de recherche, etc.
   •     Mercure notifie le joueur concerné dès que l'événement est traité.



Ressources — lazy calculation
La production de ressources n'est pas calculée à intervalle fixe. On stocke :
   • current_stock : stock actuel au dernier calcul
   • production_rate : taux de production par seconde
   • last_updated_at : horodatage du dernier calcul


Le stock réel est calculé à la demande :
  stock_réel = current_stock + (production_rate × secondes_écoulées)



La persistance n'a lieu que lors d'une action qui consomme des ressources (lancement de
construction, envoi de flotte, etc.). L'interface affiche une estimation JavaScript côté client à titre
informatif entre deux requêtes.

   •    La carte est générée en amont et chargée au démarrage du serveur. Elle ne change pas
        pendant la partie.
   •    Structure : Univers → Galaxies → Systèmes stellaires → Planètes (1 à 9 par système).

   •    La visibilité est gérée via une table PlayerDiscovery (Fog of War) : chaque système

1.4 Planètes et ressources
   •    Chaque planète a une position (1 à 9) par rapport à son étoile.
   •    La position influe sur les taux de production de base :
          ◦ Position proche de 1 (proche de l'étoile) : bonus métal/carbone/énergie, malus
             hydrogène.
          ◦ Position proche de 9 (loin de l'étoile) : inverse.
   •    Les ressources sont stockées par planète, pas globalement par joueur.
   •    Les ressources disponibles sont : métal, énergie, antimatière, hydrogène, carbone.
        D'autres pourront être ajoutées.
   •    Le transport inter-planètes se fait via des flottes équipées de vaisseaux cargo.

1.6 Vaisseaux
   •   Les vaisseaux sont définis dans des fichiers YAML. Ce sont des données statiques de
       catalogue.
   •   Il n'y a pas de notion de niveau sur un vaisseau. La recherche débloque des vaisseaux

   •   Une flotte peut contenir des vaisseaux de types différents (ex : 5 chasseurs + 5

   •   Les vaisseaux construits ne peuvent pas être améliorés ni recyclés.

1.7 Construction de vaisseaux
   •   La construction se fait planète par planète. Chaque planète avec un chantier spatial a sa
       propre file de construction.
   •   Un seul chantier par planète. La construction en parallèle est possible sur des planètes
       différentes.
   •   Temps de construction : linéaire (1 vaisseau = 1 min → 10 vaisseaux = 10 min). Réduit
       par le niveau du chantier et les technologies.
   •   La file est stockée en BDD (ShipyardQueue), un message RabbitMQ est émis à chaque
       ajout avec le délai correspondant.
   •   À la fin de la construction, les vaisseaux sont ajoutés à la flotte de la planète. Si une ligne
       FleetShip avec ce slug existe déjà, on incrémente la quantité.

1.8 Flottes
   •     Une flotte appartient à un joueur, pas à une planète. La planète d'origine est mémorisée
         pour le retour.
   •     Statuts possibles : idle, traveling, returning, in_combat.
   •     Une flotte peut contenir plusieurs types de vaisseaux (plusieurs lignes FleetShip avec des
         slugs différents).
   •     Le transport inter-planètes utilise exactement le même mécanisme qu'une flotte de
         combat.
   •     Une sonde est un vaisseau comme les autres (construite, envoyée, détruite à l'arrivée).
         Elle découvre toutes les planètes du système cible.
           ◦ Il y a deux types de sondes :
               Espionnage => espionne un planète en particulier
               Exploration => découvre les planètes d’un systèmes
   •     La colonisation consomme le vaisseau colonie à l'arrivée.



1.9 Système de recherche
   •     1 recherche active maximum par planète (laboratoire requis).
   •     Si une technologie est en cours ou en queue sur une planète, elle ne peut pas être lancée
         sur une autre planète simultanément.
   •     Les niveaux de technologie sont globaux au joueur (communs à toutes ses planètes).
   •     Le niveau du laboratoire est local à la planète et influe uniquement sur la vitesse de
         recherche et les items à rechercher (indirect via les prérequis du yaml).
   •     Les technologies ont deux rôles :
           ◦ Déblocage : prérequis pour construire un vaisseau, un bâtiment, ou accéder à une
              autre technologie.
           ◦ Amélioration de performance : bonus de stats (précision, tracking, etc.) appliqués à
              la flotte du joueur.


       Les bonus technologiques sont calculés au moment du lancement du combat (quand la flotte arrive à
       destination), pas au moment de l'envoi de la flotte. Une technologie terminée pendant le trajet est
       donc prise en compte. Une technologie terminée pendant le combat lui-même ne l'est pas.




1.10 Catalogues statiques en YAML
Tout ce qui est données de game design (stats des vaisseaux, coûts, formules de scaling des
bâtiments, arbre technologique, matrice de combat) est stocké dans des fichiers YAML
versionés dans le code source, pas en base de données.


Avantages :
   •     Historique complet des modifications via Git (qui a changé quoi, quand, pourquoi).

Space Empire — Document de conception technique



   •     Impossible de modifier silencieusement une stat en production sans commit visible.
   •     Pas de migration de BDD pour un simple nerf ou buff.


Ce qui reste en BDD (état dynamique du jeu) :
  • Ce que le joueur possède (vaisseaux, bâtiments, technologies débloquées).
  • Les niveaux actuels des bâtiments et technologies.
  • Les stocks de ressources et les files de construction/recherche.
  • Les flottes et leur état.


       Quand un YAML est modifié (nerf/buff), les effets s'appliquent immédiatement à tous les calculs
       futurs. Les vaisseaux déjà construits utilisent les nouvelles stats. Ce comportement est volontaire et
       documenté.




1.11 Système de prérequis unifié
Vaisseaux, bâtiments et défenses partagent le même format de prérequis dans leurs YAML :
   • technologies : liste de { slug, level } — prérequis global au joueur.
   • buildings : liste de { slug, level } — prérequis local à la planète.
   • ships : liste de slugs — le joueur doit avoir « débloqué » ce vaisseau (ses propres
      prérequis sont satisfaits récursivement).


Pour les bâtiments, les prérequis sont définis par palier de niveau. Pour construire le niveau N,
on applique les prérequis du palier inférieur ou égal le plus proche.


       Un vaisseau est « débloqué » si tous ses unlock_requirements sont satisfaits, évalués
       récursivement. Il n'est pas nécessaire d'en avoir construit un — il suffit d'en avoir la capacité.




1.12 Système de combat
Le combat est calculé entièrement côté serveur au moment de l'arrivée de la flotte. L'issue est
connue immédiatement. Les logs sont ensuite rejoués côté client pour l'affichage progressif.


Déroulement
   •     Le combat se déroule en rounds (nombre maximum défini, au-delà la flotte attaquante bat
         en retraite).
   •     Chaque vaisseau est une entité individuelle dans le resolver (pas un pool).
   •     Au début de chaque round, chaque vaisseau choisit sa cible parmi les ennemis
         (probabiliste).
   •     Un vaisseau peut être détruit avant d'attaquer dans le même round.
   •     Chaque vaisseau effectue un nombre de tirs aléatoire (entre 1 et son max).



                                                                                                            Page 6

   •    À la fin du combat, les survivants retrouvent leurs HP complets (pas de HP persistant
        entre combats).


Formule de toucher
  Chance de toucher = clamp(15 ; 95 ; Précision + Tracking - Esquive_cible +
  (Signature_cible / 5) - 15)


Paramètres des vaisseaux impliqués :
 Stat                  Rôle
 precision             Capacité générale à toucher
 tracking              Capacité à suivre les cibles agiles (anti-légères)
 evasion               Capacité de la cible à esquiver
 signature             Facilité à être touché (gros/lent = signature élevée)



Modificateurs de dégâts (matchup)
  Dégâts finaux = Attaque de base × modificateur de contre


 Situation                          Modificateur          Multiplicateur
 Contre fort                        +30%                  × 1.30
 Contre léger                       +15%                  × 1.15
 Faible contre                      -15%                  × 0.85
 Mauvais contre                     -30%                  × 0.70



Boucle pierre-feuille-ciseaux
  Chasseur / Intercepteur       →    Bombardier
  Bombardier                    →    Défense au sol / Cuirassé / Capital Ship
  Escorte                       →    Ailes légères
  Croiseur / Cuirassé           →    Escorte
  Capital Ship                  →    Croiseur / Cuirassé
  Défense au sol                →    Chasseur / Intercepteur / Corvette

4.2 ShipCatalog — service Symfony chargé au boot
  // src/Game/Catalog/ShipCatalog.php


  class ShipCatalog
  {
       /** @var array<string, ShipDefinition> */
       private array $ships = [];


       public function __construct(string $configDir)
       {
           // Scan du dossier — 1 fichier YAML par vaisseau
           foreach (glob($configDir . '/ships/*.yaml') as $file) {
                $data = Yaml::parseFile($file);
                $slug = $data['slug'];
                $this->ships[$slug] = ShipDefinition::fromArray($slug, $data);
           }
       }


       public function get(string $slug): ShipDefinition
       {
           if (!isset($this->ships[$slug])) {
                throw new \InvalidArgumentException("Ship type '$slug' not found");
           }
           return $this->ships[$slug];
       }


       /** @return ShipDefinition[] */
       public function all(): array
       {
           return $this->ships;
       }
  }

       public function check(
              array   $requirements,
              Player $player,
              Planet $planet,
       ): RequirementResult {

              // Vérification des technologies (niveau global joueur)
              foreach ($requirements['technologies'] ?? [] as $req) {
                  $playerLevel = $player->getTechnologyLevel($req['slug']);
                  if ($playerLevel < $req['level']) {
                       $failures[] = new MissingTechnology($req['slug'], $req['level'],
  $playerLevel);
                  }
              }


              // Vérification des bâtiments (niveau local planète)
              foreach ($requirements['buildings'] ?? [] as $req) {
                  $planetLevel = $planet->getBuildingLevel($req['slug']);
                  if ($planetLevel < $req['level']) {
                       $failures[] = new MissingBuilding($req['slug'], $req['level'],
  $planetLevel);
                  }
              }


              // Vérification des vaisseaux prérequis (récursif)
              foreach ($requirements['ships'] ?? [] as $shipSlug) {
                  if (!$this->isShipUnlocked($shipSlug, $player, $planet)) {
                       $failures[] = new MissingShipUnlock($shipSlug);
                  }

           }


           return new RequirementResult($failures);
       }


       private function isShipUnlocked(
           string $shipSlug,
           Player $player,
           Planet $planet,
           array     $visited = [],
       ): bool {
           // Protection contre les cycles dans les prérequis
           if (in_array($shipSlug, $visited, true)) {
                throw new \LogicException(
                      'Cycle dans les prérequis : ' . implode(' -> ', $visited) . ' ->
  ' . $shipSlug
                );
           }


           $visited[]      = $shipSlug;
           $definition     = $this->shipCatalog->get($shipSlug);
           $requirements = $definition->unlockRequirements ?? [];


           $result = $this->check($requirements, $player, $planet);
           if (!$result->isSatisfied()) {
                return false;
           }


           // Récursion sur les vaisseaux prérequis
           foreach ($requirements['ships'] ?? [] as $requiredSlug) {
              if (!$this->isShipUnlocked($requiredSlug, $player, $planet,
  $visited)) {
                      return false;
                }
           }


           return true;
       }
  }

                    if ($effect['type'] !== 'stat_bonus') {
